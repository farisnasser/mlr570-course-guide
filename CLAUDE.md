# MLR570 Course Guide — project rules

A static website that walks Faris through his MLR570 (Advanced Machine Learning, AUS, Fall 2026) course notes, part by
part: the notes **verbatim**, the PDF's own figures, and interactive visuals where they make a concept click.
Separate from the Survey Visual Atlas (`../survey-atlas`): never edit or depend on that repo.

## The one rule that matters
**The notes PDF is the single source of content.** `reference/MLR570_Course_Notes.pdf` — "nothing more and nothing less".
Every sentence, equation, table, box, worked example and quick-reference table is copied verbatim, in the PDF's order,
with its numbering. No added explanations, no rewording, no summaries. If you find an actual error in the notes, do not
change it: tell Faris and let him decide. The only additions are the interactive visuals, which:
- add no information: labels, captions and readouts use only the notes' own terms, symbols and numbers
  (a one-line caption saying what to drag is fine);
- run the real math (real matrices, distributions, solvers); never sculpt a picture to look right;
- open on the notes' worked example where one exists and reproduce exactly its numbers;
- sit in a frame marked "Interactive" so they never read as part of the notes.

## Layout
```
index.html                course map: chapters -> parts -> sections, progress, continue
part.html?p=1.1           one part per page: chapter/part header, notes, figures, visuals, journey rail, prev/next
src/theme.css             tokens; box legend colours (red = key definitions/results, blue = why it matters in ML,
                          amber = additions/clarifications); visual colour language (shared with the Atlas)
src/site.css              shell + compact PDF-like notes styles + visual frames
src/notes.js              notes.md -> HTML (syntax documented at the top of the file)
src/app.js                part page boot; src/home.js course map; src/progress.js (localStorage)
src/viz/plane.js          2D canvas stage: transformed grids, arrows, labels, draggable handles, tween()
src/viz/la.js             2x2 / small-matrix numerics (det, inverse, rank, eig2, svd2, Jacobi eigSym, svd)
src/viz/three-lite.js     three.js layer for 3D visuals (lazy-loads three@0.128.0 + OrbitControls; z-up math coords)
src/viz/ui.js             sliders, segmented buttons, KaTeX readouts
src/viz/stats.js          exact normal / uniform / exponential pdf+cdf, erf, seeded RNG (mulberry32) + gauss
                          (plane.js also exports Chart: independent x/y ranges, axes, area/rect/fn helpers)
parts/<id>/notes.md       the part's notes, verbatim (no title: the header comes from data/course.json)
parts/<id>/figures.json   the PDF figures to extract (page, rect in PDF points)
parts/<id>/fig/*.svg      GENERATED by scripts/extract_figures.py (exact vector extracts, dark-theme recolour)
parts/<id>/viz.js         export default { '<viz-id>': { title, mount(frame) -> api } }
data/course.json          GENERATED by scripts/build_course.py from the PDF outline (never edit by hand)
scripts/check/<id>.py     recomputes every number of the part's worked examples and visual defaults (1_1.py ...);
                          common_rng.py ports the JS RNG so checks rebuild the visuals' datasets; run_all.py runs all
research/notes-findings.md  discrepancies found in the notes (reported to Faris, never silently fixed)
scripts/serve.py          dev server, port 8590 (preview "course-guide" in .claude/launch.json)
research/visual-plan.md   which visual for which concept, per part
```

## Notes syntax quick reference (full list in src/notes.js)
`## 1.1.1 Title` section · `### Head` bold run-in head · `$..$` / `$$..$$` math (KaTeX 0.16.9) · `:::def`, `:::ml`,
`:::add`, `:::ex`, `:::model` (teal "Mental model"), `:::plain`, `:::big` boxes (title after the kind) · `:::cap` (a PDF
figure caption, small and centred) · `:::cols [even|figleft]` + `:::col` ·
`:::fig <id>` PDF figure · `:::viz <id> | caption` visual · tables with an optional `|{stack}` first line (stack into
cards on phones). A paragraph line ending in `\` is a hard line break. In table cells never write a bare `|`:
use `\lvert x\rvert`; `\|` (norm) is fine.

## Dev and audit
`python scripts/serve.py` → http://localhost:8590/part.html?p=1.1. On localhost the page exposes `window.__guide`
(`errors`, `mountAll()`, `viz[id]` APIs with `state()`/`reset()`). Every part must pass: its check script (`python -I scripts/check/run_all.py`),
0 KaTeX errors, 0 page errors, 0 px horizontal overflow at 375 px, every visual mounted. Commit messages end with
`Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Publishing
Local only until Faris approves. Before creating a GitHub repo or enabling Pages, ask him whether it should be public
(it contains his course notes and the PDF).
